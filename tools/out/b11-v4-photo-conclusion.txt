一、改了什么（产品侧）
  1. design.css :root 新增三个 token，值由 tools/out/photo-tint-probe.js 在 75 张镜像照上算出来：
       --photo-veil:rgba(33,26,19,.10)   向同一颜色做凸组合，每通道 σ 乘 (1−α)
       --photo-look:saturate(.94)        乘性滤镜，只把整批一起压
       --photo-edge:rgba(33,26,19,.20)   照片与纸面的分界线（不随暗色翻转）
     探针账（64×64 采样）：单用滤镜 σ(S) 只降 4%；合用 veil .10 + saturate(.94) → σ(S) −15%、σ(色温 R−B) −16%，
     明度均值 45.3% → 41.5%；α 再大就吃掉暗部（α=.18 时「过暗样本」4 → 8 张），故停在 .10。
  2. 统一挂载块（design.css 1601–1621）：10 条表面吃滤镜、6 条容器吃 veil、4 条容器 inset 环、
     3 条裸图外圈 1px、暗色档外圈翻 --edge-hair。占位态用 :has(>img) 排除，空态不被压成脏灰。
  3. 封面（map.css 894 / 898 / 1331）：inset 环 + 下压式自带影与 veil 合并进同一个 ::after。
  4. 顺手清掉零调用者的死规则 .card .media 一族（4 条）。

二、像素对账（tools/smoke-photo.js C 段，16 条断言全过）
  同一张封面 <img> 元素截图 → 64×64 平均亮度（0–255 域）：
    原样（摘掉两个 token）= 106.68   带压色 = 98.05   降幅 = 8.63（≈3.4%）
  断言区间 5–14：低于 5 说明压色只写在 CSS 里没落到画面，高于 14 说明压过头吃暗部。

三、452dp 视口目测结论（诚实版）
  · 封面（topic-sheet 实景大图）：饱和度收敛后与纸面暖墨同调，1px 内圈把「照片贴在纸上」这条界线立住了；
    单张封面的变化是「细微但可测」，不是换了一种观感。
  · 列表页（topic-list）：前后几乎看不出差别。**这一屏真正刺眼的不协调不在照片之间，而在
    带内嵌文字的卡通占位 SVG 与真实照片混排**（花舞人间 / 九峰山 是生成图，新津老君山 是真照片）——
    压色治不了它，属于图源问题，归入下一方向。
  · album.seed 前后 PNG 字节数完全相等（151994）：该态封面走 .al-cover__img + .al-cover__shade 一族，
    本轮有意不重复压（已有暗色渐变层），所以像素零漂移——这是预期结果，不是漏挂载。
  · 同一屏另有一处实测缺陷（前后都在）：海拔坐标轴标签 6000m / 3000m / 2000m / 1000m / 海平面 互相压字，
    与「1000m」和「海平面」重叠最严重 → 记入下一轮（专题面板图表）。

  · 像素侧：tools/visual-check.js 64 态复跑 → **79 张 / 79 PASS / 0 FAIL，每态 0.00%**，耗时 380.6s，
    日志 tools/out/b11-v4-visual-rerun.txt。**但这条对 UI-4 是「零覆盖」，不是「零回归」**：
    visual-check 为了确定性拦掉所有 http(s) 请求，本地镜像照（images/sites/*.jpg）与种子照（art/photo-*.svg）
    一律加载失败 → 全站照片渲染成 .img-fallback 占位纹，滤镜与 veil 作用在一块没有像素的 <img> 上，
    画面上当然一点不动（album.seed 前后 PNG 字节数完全相等也是同一个原因）。
    所以 UI-4 的实际回归证据只有两条：smoke-photo.js 的元素级像素对账 + 本文件那组放行 http 的对比图。
    → 已登记为 #79 的欠账：给 visual-check 加「同源图片放行」的照片态，让这类改动有像素闸门可管。

# 行迹 TRACE · 节点规模化规则（v1.0 · 2026-08-13）

> 目的：让项目从当前 **3432 个专题节点 / 3253 个全国节点** 平稳扩到 **5000+ / 10000+**，不因数据增长出现渲染卡顿、白屏、主题错乱。所有新增数据与功能必须遵守本规则。
> 适用范围：`F:\MyAi\trace\lvyou-v2`（含 Android 壳 assets 同步）。

---

## 1. 数据规范（新增/修改节点必读）

### 1.1 节点字段（全部必填）

```json
{
  "name": "景点名（唯一，全库不可重复）",
  "label": "展示名（可与 name 相同）",
  "region": "省/自治区全称，如「山西省」——⚠ 必填，缺失会导致 LOD 聚合退化为「其他」",
  "city": "地级市/州，如「大同市」",
  "county": "区县，如「平城区」",
  "theme": "主题，**必须在该省注册表 `themes` 里**（见 1.2）",
  "elev": 海拔整数，未知填 0，
  "best": "最佳季节，如「4-10月」，未知填「全年」",
  "lat": 纬度（WGS84 近似，境内 15~55），
  "lng": 经度（境内 70~140），
  "desc": "60~100 字介绍，有真实信息量",
  "wiki": "维基词条名，可空字符串"
}
```

**字段缺失后果**（均为真实踩坑）：
- 缺 `region` → LOD 低缩放时全部节点聚合到「其他」一个胶囊，专题页看起来"没有数据"（山西 data.js 504 节点踩过）
- `theme` 不在注册表 → 节点显示灰色默认色、主题筛选/图例里找不到它

### 1.2 主题规则

- 每个省注册表 `themes` 是**该省唯一合法主题集**，新增节点主题必须取自其中
- 全国性新主题（如「古城古镇」）若该省注册表缺失：**优先补注册表**（补色值），不要改节点主题
- 同义主题统一走 `THEME_ALIAS` 归一（全国地图汇总用），新增省份主题必须检查别名表

### 1.3 文件规范

- 每省一个 `xx-data.js`（`window.SITES = [...]`），一个 `xx-food.js`
- 单文件 ≤ 300KB；超过后按城市拆 `xx-data-{city}.js` 并在注册表配置多文件
- 数据文件内 `"lat":` 计数 = 节点数（gen-counts.cjs 按此统计）
- 文件名与注册表 `dataJs` 必须一致；**勿用缩写复用**（qz-data.js 实为青藏数据，已列为待改名项）

## 2. LOD 与渲染规则（node-lod.js）

| 场景 | 规则 |
|---|---|
| 跨省/全国页 | 区域→城市→县区→节点 四级，≤30 节点直接全节点，≤80 到重要节点，>80 城市聚合 |
| 省内页 | 城市→县区→节点，>150 节点启用县区层 |
| 聚合上限 | 视野内聚合组 >26 且跨多父级 → 逐级回退，最粗层仍过密 → 直接节点层兜底 |
| 性能预算 | 单页节点 ≤3000 无需改动；3000~6000 建议列表虚拟化；>6000 全国页必须按省分块加载 |

新增节点不改变渲染逻辑，但**每个新增省必须验证**：初始 zoom 下地图不空白、放大逐级展开正常（3 个缩放档位各看一次）。

## 3. 加载与缓存规则

- 专题数据：`topic.html` 按 `?p=` 懒加载对应数据文件（已实现），**新增省不要改这个机制**
- 全国数据：`nation-data.js` 动态注入 + 骨架屏（已实现）；文件超 2MB 后必须按省拆分懒加载
- **SW 缓存版本**：任何 sw.js 内容变化必须 bump `CACHE`（当前 v9）；`activate` 白名单必须保留 `TILE_CACHE`
- **新增文件三同步**：页面引用 → `tools/gen-sw-shell.cjs` 的 CORE_JS（若为 js）→ 重跑脚本生成 SHELL
- 版本号：引用统一 `?v=YYYYMMDD` 日戳，不要各自递增（node-lod.js?v=14 的教训）

## 4. 扩省 SOP（10 步）

1. 写 `xx-data.js`（遵守 §1 规范，节点数建议 ≥100，覆盖全部地市）
2. `node tools/test-data.cjs` 跑 74 项校验（PASS 才继续）
3. 主题合法性核验：数据 `theme` ⊆ 注册表 `themes`（脚本：`tools/test-data.cjs` 覆盖项）
4. `topic-meta.js` 注册一条（p/title/dataJs/foodJs/center/zoom/regionShort/REF/tripKey/themes/themeIcons/dayColors）
5. 入口卡片：explore-map.html 专题列表加一张
6. `node tools/gen-counts.cjs` 更新首页计数（若首页有该专题卡片）
7. 重跑 `node tools/gen-sw-shell.cjs` 重建 SHELL + bump 缓存版本
8. 语法检查全部 js（node --check）
9. 同步 assets（robocopy /MIR）→ 重新打包 APK
10. 真机冒烟：专题页地图/列表/主题/路线/美食 5 个 Tab + 离线访问

## 5. 性能预算（节点规模 vs 措施）

| 全国节点 | 必须项 |
|---|---|
| ≤3500（现状） | 现状即可：nation 动态加载 + LOD |
| 3500~5000 | 列表虚拟滚动（专题列表分块渲染） |
| 5000~8000 | 全国页按省分块懒加载 + 瓦片按省包 |
| >8000 | 服务端/静态 JSON 预生成 + 索引文件，前端按查询拉取 |

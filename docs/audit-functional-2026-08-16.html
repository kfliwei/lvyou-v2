三、核心发现

A1 · AI 是「半扇门」，无 Key 用户拿不到核心价值

成果工坊的「旅程故事」、游记「AI 润色」、专题「定制路书」三者，在未配置 DeepSeek Key 时 直接返回报错提示（results.js:32 判 Ai.hasKey()），没有本地降级。 只有「年度报告」做了统计式本地兜底（review.html:438）。 这意味着：普通用户（大概率不自备 Key）打开应用，AI 卖点里 3/4 是「点了就报错」。

建议：故事/润色/路书补本地模板兜底（类似年报），或把「AI 生成」与「本地模板生成」做成可选，别让功能空转。
B1 · 想去清单「规划行程」两步跳转缺引导

wishlist.html:433 的按钮只执行 location.href='planner.html'， 心愿节点不会自动带入；到 planner 页后还需用户自己发现并点「已收藏 N 处，一键串起来」按钮。 链路通，但一步跳转 + 一次手动点击，中间无任何「下一步点哪里」的衔接。

建议：按钮跳转时带 ?from=wish 参数，planner 页检测后高亮引导「一键串起来」；或直接跨页调用 plannerSeedWish()。
B2 · 「定制路书」入口太深

路书只藏在专题地图某个景点详情 sheet 的「更多」菜单里，用户不在专题里点开具体景点就永远找不到。 成果工坊（review 页）也只挂了纪念册/图鉴/故事三入口，没有路书。

建议：在回顾页成果工坊补一个「路书」入口（无站点时提示先去专题），或放到行程规划结果页。
✅ 数据层已能支撑功能

经过本轮补全，介绍为空清零（8050 站），「必去/网红」标识从 562 → 1764 个， 搜索支持 desc 匹配 + 多关键词分词 + 主题筛选 + 省份精准跳转 + 游记定位。 数据质量不再是功能短板，反而成了亮点。

五、结论与建议优先级

项目功能骨架完整、九成链路闭环，数据层经过本轮补全已是亮点。 当前最大的功能性短板是 AI 功能的 Key 门槛——它既是产品的核心差异化卖点，又是「无 Key 就报错」的半成品体验。

优先级事项成本
①给「故事/润色/路书」补本地模板兜底（对齐年报）中
②想去清单「规划行程」一步带入心愿 + 引导低
③回顾页补「路书」一级入口低
三处都是「成本低、收益高」的体验修补，且不涉及数据/架构重构，可一轮完成。需要我直接修，说一声即可。

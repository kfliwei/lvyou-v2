三、本次审核新发现问题

3.1 🔴 双工程漂移:缓存修复没有修到真正构建的工程

这是本次审核最有价值的发现。项目存在两份 Android 壳代码:

  • git 仓库副本 lvyou-v2/android_app/(versionCode 31 / v2.21)
  • 实际构建工程 lvyou-v2-android/(versionCode 33 / v2.23,所有 APK 产物在此)

8-17 的提交 5f5b247("冷启动不再每次清空缓存 → 改为版本号变化时才清理,保留瓦片 HTTP 缓存")只改了 git 仓库副本的 MainActivity.java。实际构建工程里的 MainActivity.java 仍是旧版--onCreate 中无条件 webView.clearCache(true)。

后果:v2.22、v2.23 两个已出货的 APK 上,"每次冷启动清空地图瓦片缓存、弱网首屏白板"的问题依然存在。修复代码其实已经写好了,只差同步过去。

修复成本:一次文件复制。同理建议核对两工程的其它差异(本次抽查 build.gradle/manifest 一致性正常,但 XfVoiceEngine 等未逐一 diff)。

3.3 🟠 存储可靠性:架构已升级,仪表没跟上

先肯定:旧审核的 F1(localStorage 5MB 天花板)已在 8-15 落地解决--游记迁 IndexedDB(含版本迁移框架 + 增量 diff 写回),媒体优先走原生 file:// 落盘,架构层面是对的。

但仪表盘还是旧的:settings.html 的存储统计仍只统计 localStorage['travelNotes'] 与 tn_audio--前者早已不是主存储,后者是旧通道残留。用户看到的存储用量是错的(大概率显示接近 0,而真实数据在 IndexedDB 和 files/ 目录里),既无法感知真实占用,也没有 navigator.storage.estimate() 的配额预警。旧审核指出的「统计口径不准」在架构升级后反而更不准了。

修复方向:统计改为 navigator.storage.estimate()(总量/配额)+ IndexedDB 计数(笔记条数/媒体字节);导出备份同步覆盖 IDB + files/ 媒体。

3.4 🟡 其他核实结论

  • 离线地图仍缺失(旧 F2 未解):SW 只缓存应用壳,瓦片请求失败无降级提示。旅行场景(山区/高原弱网)地图白板的体验缺口仍在。方案:leaflet.offline 类 IDB 瓦片缓存,或至少加「瓦片加载失败」轻提示。
  • Android 壳的既有欠账未清(旧报告 ★1/★2 项):构建工程 onDestroy 仍未 webView.destroy()(内存泄漏)、onRequestPermissionsResult 仍未实现(权限被拒静默失败)、仍是 debug 签名 + minifyEnabled false、无 ABI 精简(多背 1.2MB armeabi-v7a)。
  • 到达提醒能力受限:3km 检查依赖页面在前台运行,WebView 形态下无后台通知能力--受架构限制,属已知边界,不算缺陷,但值得知晓。

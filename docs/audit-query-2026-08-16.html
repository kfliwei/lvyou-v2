一、结论摘要

架构方向清醒、持续收敛（上一轮的死代码/重复实现/双 :root 已清理）。本轮从「功能」视角切入，发现查询/检索能力存在明显短板，其中 3 个 A 级问题会直接让用户「搜得到却点不到、搜不到想搜的」。

二、查询/检索能力弱项（核心发现）

A1 搜索结果无法跳转到对应省份专题

搜索索引 nation-index.js 里的省份用简称（山西），而 search.html 的跳转映射 PROV_KEY 用全称（山西省），导致匹配永远落空：

// nation-index.js 实际数据
"云冈石窟|云冈石窟|山西|大同市|..."   // region = "山西"（简称）

// search.html 的映射（全称 + 本身还错乱）
PROV_KEY = { '山西省':'sx', '广西壮族自治区':'gy', '云南省':'gy', '江西省':'cz', ... }

→ PROV_KEY['山西'] = undefined，于是所有景点搜索结果点击后都降级跳「全国地图」，而不是用户搜到的那个省。映射本身也错乱（广西/云南共用 gy、江西映射 cz）。

A2 搜索无法匹配「景点描述」

搜索索引只有 9 个字段（无 desc），但匹配代码却引用了 s.desc：

// nation-index.js 每行只有 9 列
name|label|region|city|county|theme|flag|lat|lng   ← 没有 desc

// search.html 匹配时却读 s.desc（恒为 undefined）
var hay = (s.name + s.label + s.region + s.city + s.county + s.theme + s.desc)  ← desc 无效

→ 搜 四大石窟、海内孤品 这类描述性关键词，永远搜不到（它们只存在于 data.js 的 desc 字段里）。搜索被降级成「只能搜名字/地名/类型」。

A3 搜索仅「子串匹配」，无拼音 / 模糊 / 分词

  • 无拼音：搜 xiangshan、ys 找不到「香山」「云冈」（中文景点无法用拼音/首字母定位）
  • 无容错：打错一个字（「云岗」vs「云冈」）就搜不到
  • 无多关键词：搜「北京 茶馆」整串 indexOf 匹配失败，不支持空格分词

B 级（体验弱项，不阻断）

B1 游记结果无法精准定位

搜到某篇游记，点击只跳 travel-map.html 首页，不能定位到具体那篇——用户得自己在列表里再翻一遍。

B2 游记搜索字段不全、无地区筛选

游记匹配了 title/siteName/text/raw/tags，但漏了 weather/province/city；且景点有「地区 chips」筛选，游记没有对应筛选。

B3 搜索全量加载 662KB 索引

nation-index.js 一次加载 7833 站（662KB），首屏偏重，无按省懒加载。

B4 无主题/类型筛选

搜索页只有「地区」chips，无法按「石窟 / 古塔 / 寺庙 / 美食」等类型筛（数据里明明有 theme/ty 字段）。

三、数据层架构弱项

数据源「双轨漂移」

数据源覆盖省份字段字段数
data.js山西（552 站）全称「山西省」name/flag/label/region/city/county/dy/ty/lat/lng/desc/wiki/img
nation-index.js全国（7833 站）简称「山西」name/label/region/city/county/theme/flag/lat/lng
各省 *-data.js单省全称各不统一

→ 同一字段（省份）三种写法、同一站点字段集合不一致，搜索、跳转、统计、图例都会踩坑，这是 A1/A2 的根源。

四、其它功能弱项

C1 AI 核心卖点依赖用户自备 Key

AI 润色 / 年报 / 旅程故事 / 定制路书，都依赖用户自填 DeepSeek Key（tn_aiKey）。无 Key 时降级为本地模板，体验打折、门槛偏高。

C2 无云同步 / 账号体系

数据仅存本地（localStorage），换机靠手动「导出备份 → 导入」。无账号、无云同步。

C3 离线能力有限

sw.js 只预缓存约 74 个核心文件，各省数据（大文件）不缓存，离线时地图/景点数据不全。

五、改进建议（按投入产出比排序）

优先级建议成本收益
①统一省份字段命名（nation-index 改全称，或 PROV_KEY 按简称重映射），修 A1低高 · 搜索结果可精准跳省
②nation-index 补 desc 字段 + 搜索匹配 desc，修 A2低高 · 可按描述内容搜索
③加拼音搜索（内置轻量拼音表 / 首字母索引）中高 · 中文景点可拼音定位
④游记结果带 ?note=id 精准定位到具体那篇低中
⑤搜索页加「主题/类型」筛选 chips低中
⑥多关键词分词（空格切分 + 全部命中）低中

①②⑤⑥ 均为低风险改动，可一轮完成；③（拼音）需引入拼音映射表，建议单独评估。

01 现状：这是一款已经「能用」的产品

核心链路（浏览 → 收藏 → 到达 → 记录 → 回顾 → 分享）已全部打通，且每个环节都有真实落地：3362 节点全库、语音游记 + AI 润色、行程规划 + 高德导航、心愿单打卡、年度报告 + 足迹海报。视觉完成度是同量级产品里少有的。接下来的增量不该是「加页面」，而是「把每条链路做深、做闭环」。

02 功能完善建议（按价值排序）

P0 · 全局搜索缺失

跨全库景点搜索 + 语音搜索

当前搜索只覆盖首页游记 + 8 个注册专题；3362 节点全国库搜不到。建议 topic-common.js 抽全局搜索模块：按省/主题/关键词跨库检索，入口放首页 hero + 底部导航，支持语音输入（AndroidVoice 已有）。

P0 · 收集感缺失

足迹成就体系

「记录」缺少「收集」的钩子：省份徽章、主题收集进度（71 主题）、里程成就、打卡 streak。数据全在本地（review.html 已有省份/标签统计），加成就层 = 复用统计 + 徽章 UI，把工具变成「养成的收藏夹」。

P0 · 跨专题行程

旅行计划生成

现在行程只能在一个专题内勾选。增量：心愿单多选 → 跨省合并成计划（按地理位置排序、每日分组）→ 一键导出 GPX（vault.js 已有导出能力）→ 分享计划卡。把「想去」变成「能去」。

P1 · 位置服务

到达提醒（地理围栏）

打卡目前靠手动。WebView 有定位权限：对心愿单节点设 3km 围栏，到达时通知「你已到 X 附近，记录一下？」。这是把「浏览用户」变成「记录用户」的最短路径。

P1 · AI 对话化

行程助手（自然语言）

DeepSeek key 已在设置页。增量：对话框输入「5 天云南怎么走」，AI 基于注册表数据返回带节点的行程草案，一键导入行程引擎。比泛问答更贴产品。

P1 · 数据风险

自动备份

全部数据在本地 IndexedDB，导出/导入靠手动。建议：设置页一键导出到「下载」目录 + 定期提醒（每月首次打开弹提醒）。WebDAV 同步按既定决策不做，但「防丢失」要有底线。

P1 · 节点 UGC

景点与游记双向关联

节点详情只读。增量：节点详情显示「去过的人留下的笔记」入口、我的游记自动挂到对应节点（按坐标匹配已可行）。让 3362 个节点变成活的。

P2 · 列表性能

列表虚拟滚动

专题列表 500+ 条全量渲染 DOM。加 IntersectionObserver 分块渲染（每屏 20 条），滚动手感立刻变好，改动集中在 topic-common.js renderList。

P2 · 分享矩阵

横版海报 + H5 分享页

现有足迹海报是竖版 1080×1620。补横版 16:9（微信/朋友圈更友好）+ 「我的年度足迹」H5 分享页（复用 AI 年报 + 海报数据）。传播是 PWA 唯一的增长引擎。

05 建议路线图（90 天）

Phase 1 · 30 天

全局搜索 + 首启引导 + 列表虚拟滚动

搜索是三件事里性价比最高的一件：一次抽取，首页/专题/全国三处受益。同时完成 SW 机制治本，专题页恢复离线。

Phase 2 · 31~60 天

成就体系 + 到达提醒 + 跨专题行程

成就层直接复用 review 统计；围栏提醒把「收藏」转「打卡」；行程合并让心愿单从清单变成计划。

Phase 3 · 61~90 天

AI 行程助手 + 横版海报/H5 分享 + 自动备份

AI 助手是差异化亮点；分享矩阵是 PWA 的增长引擎；备份是数据安全底线。

一句话总结：产品已过「能用」，正处在「好用」的门口。最该做的三件事——全局搜索（信息入口）、成就体系（留存钩子）、到达提醒（记录转化）——全部可以基于现有数据与代码增量实现，不需要新架构。

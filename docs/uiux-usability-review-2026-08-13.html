Usability Review · 2026-08-13

行迹TRACE v2.0 用户友好性评估

视角：技术大佬（架构与质量）＋ 普通用户（上手与使用）｜对象：F:\MyAi\Trace Web 前端（7782 节点 / 50+ 页面 / 2.8MB 数据集）
24处整页 location.href 跳转
10处原生 alert/confirm（8 alert + 2 confirm）
0处 aria 无障碍属性
2.8MBnation-data.js 单文件全量加载
5MBlocalStorage 容量天花板（录音 base64 存储）

一、总体判断

设计底子与功能厚度都是优秀的：宣纸/墨/朱砂的中式语言统一、毛玻璃胶囊导航、安全区适配、骨架屏、空态文案、打卡→语音记录闭环、语音双引擎容错——这些在同类个人项目里非常少见。但"用户友好性"的短板恰好集中在 危险操作保护、系统级弹窗、反馈一致性、性能体感 四类，全部是"差最后一公里"的问题：功能都有了，但普通用户在关键时刻得不到温柔对待。

二、两个视角看同一批问题

🧠 技术大佬视角

  • 2.8MB 单 JS 全量加载：nation-data.js 压缩成 8 行，首页/地图/搜索都要解析，低端机首屏明显卡顿
  • localStorage 5MB 天花板：录音 base64 膨胀 33%，游记一多静默写入失败 = 数据丢失（原生 files 桥已存在未用）
  • 搜索无防抖：oninput 直接全量遍历 7782 节点拼 HTML
  • 无 SPA 路由：24 处整页跳转 + 冷启 clearCache，每次导航全量重载
  • 无障碍为零：aria- 0 处、emoji 当图标、无 focus-visible 管理
  • 一致性技术债：topbar/bottom-nav 每页复制内联样式；深色模式逐页手工覆盖

👤 普通用户视角

  • 删除没有第二次机会：想去清单 ✕ 一点即删，无确认无撤销（md-manager/settings 有 confirm，这里却没有）
  • 系统弹窗跳戏：规划行程不够 2 个、语音不可用，弹出浏览器原生 alert，与整个设计语言割裂
  • 数字对不上：我的页写着"3253+ 处全库检索"，实际数据已 7782 节点
  • 搜索截断无下文：最多 60 条结果，没有"加载更多"；游记结果只能跳地图页，到不了那篇游记
  • 弱网白屏：山区/高原瓦片加载失败无任何提示
  • 首次上手无引导：核心玩法（景点→语音记录→足迹）全靠自己摸索

三、按用户伤害程度排序的问题清单

🔴 P0 — 低成本高感知，建议立即做

1. 想去清单删除无确认、无撤销（误触即丢）
同一应用里 md-manager 删游记、settings 清数据都有 confirm 保护，唯独 wishlist 的 ✕ 直接 remove。用户误触一次就丢一个心愿节点，且无恢复路径。
wishlist.html: doRemove(i) — 无 confirm、无 undo、无 toast 可撤销
2. 原生 alert 与设计系统割裂（8 处）
语音不可用、节点不足、保存失败全部走浏览器原生弹窗——宣纸毛玻璃里突然蹦出一个系统灰框。且 alert 阻塞式打断操作流。
search.html:167/168 · travel-map.html:582/622/634 · wishlist.html:116
3. 首页/我的页数据口径过时
数据已扩到 7782 节点，me.html 还写"3253+ 处全库检索"；用户会怀疑应用没更新。
me.html: 搜索全部景点 <small>3253+ 处全库检索</small>（应为 7782）
4. 搜索性能：无防抖 + 全量遍历 + 结果截断无提示
每敲一个键全量遍历 7782 节点并拼接 HTML；命中 60 条封顶，用户不知道还有更多。
search.html: $q.oninput=function(){…render();} 无防抖；hits.slice(0,60) 无"加载更多"

🟠 P1 — 重要，涉及架构或体验主线

5. 返回行为三套逻辑并存
search 带 fallback（history.length>1?back:首页），wishlist 裸 history.back()（深链进入可能直接退不出/退出应用），专题页返回按钮回首页而非回退栈。系统返回键与页面按钮行为不一致，用户会"迷路"。
search.html: history.length>1?history.back():… ｜ wishlist.html: history.back() ｜ 专题页: location.href='index.html'
6. 数据架构：2.8MB 单文件 + localStorage 天花板
nation-data.js 2.8MB 压缩 8 行全量解析；录音/照片 base64 塞 localStorage（5MB 上限）→ 写入静默失败即丢数据。原生 savePhotoFile/saveAudioFile 桥已存在却没用于媒体。
nation-data.js = 2,809,372 B ｜ settings.html refreshStorage() 仅统计 localStorage 两项
7. 弱网/离线无降级
瓦片请求失败无提示无重试；山区自驾正是这个应用的核心场景，白屏最伤信任。冷启 clearCache 还每次都清掉 HTTP 瓦片缓存。
explore-map/travel-map: L.tileLayer 无 error 监听 ｜ MainActivity: clearCache(true)
8. 触控目标偏小（多处 < 44px）
删除按钮 30px、麦克风 34px、返回键 34px、地图控件簇 40px。单手驾驶间隙操作时极易点错。
wishlist .wl-remove 30px ｜ search .mic/.back 34px ｜ travel-map .ctl 40px

🟢 P2 — 打磨项

9. 无障碍为零：aria- 0 处，emoji 当图标
全站 0 个 aria 属性；🎙🏅🗺️📖⭐⚙️🔍 直接当图标，读屏会念出 emoji 名称；无 :focus-visible 焦点样式。个人自用可缓，但分享给亲友或长辈时就是门槛。
10. 行程规划结果不可调整
贪心算法按"每天 ≤6 站、≤260km"硬编码自动分日，用户不能换天、拖拽排序、指定出发地；结果无地图可视化，只能看文字列表。
wishlist.html planTrip(): 6站/260km 常量写死；days 渲染为纯文本列表
11. 首次启动无引导
"景点详情 → ♡ 想去 → 打卡 → 语音记录"这条核心链路完全靠用户摸索；空态文案虽好，但首页没有一次性的 3 步引导或功能提示。

保留

骨架屏

search.html 加载 2.8MB 数据期间有骨架动画，等待不焦虑（但要注意骨架屏遮不住全量解析卡顿）。
保留

打卡→记录闭环

想去清单打卡后直接弹语音记录面板，链路短、意图清晰。
保留

危险操作保护

md-manager 删游记、settings 清数据都有 confirm——把这份保护补到 wishlist 即可。
保留

保留

深浅主题与动效降级

prefers-reduced-motion、安全区适配、搜索直达景点定位（topic.html?p=&q=）都是专业级细节。

五、建议落地顺序

第 1 批（0.5 天）wishlist 删除加确认/撤销 · alert 全换设计内 Toast/对话框 · 修 me.html 过时数字 · 搜索加防抖
第 2 批（1-2 天）返回逻辑统一 · 触控目标补到 44px · 瓦片失败提示 · 媒体移出 localStorage
第 3 批（2-3 天）nation-data 拆省按需加载 · 行程规划可拖拽调整 · 首启引导
第 4 批（可选）SPA 路由 · 无障碍补齐（aria/焦点/读屏）

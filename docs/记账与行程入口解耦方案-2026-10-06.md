## 1. 一句话主张

**把「一趟行程」升成一等对象，把「排期」降级成它的一个可选属性，把「钱 / 打卡 / 票 / 清单」全部挂到真实日期与行程 id 上。**
入口从「只有规划结果页的日卡底部」这一条，扩成五条常走的路；其中一条必须做到**没排过期也能记**。

不做补丁式处理（不在日卡上补空白天、不把按钮藏进更多菜单、不加二级引导文案）。

## 3. 数据契约（先定契约，再画界面）

### 3.1 记账条目加「真实日期」，日期是权威

```
tn_expense 条目：{ id, tripId, day, date, cents, cat, who, note, ts }
                                            ↑ 新增，'YYYY-MM-DD' 或 ''
```

- **写入口只有一个**（`Expense.add`），它同时落 `date` 与 `day`：`date` 由调用方给（默认今天），`day` 由 `date` 与 `trip.startDate` 反推；反推不出（行程没填出发日期）则 `day` 沿用传入值、`date` 照记。
- **读口径**：汇总/CSV/按天列表一律以 `date` 为准；`day` 只在「按计划看」的日卡视图里用作对齐锚点。这一条把 §2 里「重切分搬钱」从根上拆掉——钱不再挂在序号上。
- **金额仍全程整数分**（expense.js 头部注释的纪律不动），日期字段不引入任何浮点。

### 3.2 旧数据迁移：只读派生，绝不编日期

- `Expense.migrate()` 幂等：读到缺 `date` 的条目时，用该趟 `startDate + (day-1)` 反推；**推不出就留 `date:''`**，界面上标「日期未知」分组，不许拿 `ts` 冒充旅行日期（`ts` 是记账动作的时刻，不是花钱的那天）。
- 迁移只在内存里派生视图，真正落盘发生在下一次 `save()`；这样旧版本读到的数据仍然是完整的（多一个字段无害）。
- 备份侧要实测：`tn_expense` 的并集策略是 `m:'id'`（backup.js:32），新增字段天然随条目搬运，**不新增键、不改 schema 号**——这条要在 smoke-backup 里钉一条，不能靠推理。

### 3.3 行程侧新增两个可选字段

```
trip.realDays  // 实际走了几天（用户填，可 > 或 < days.length）
trip.logStart  // 实际出发日（默认 = startDate，允许与计划不同）
```
两者都可选、都不进 `share.js` 白名单（钱和"实际改期"都是隐私）。

### 3.4 「未编排行程」桶：入口窄的正解

- 新增常量 `Expense.FREE_ID = 'free'`，显示名「未编排行程」。
- 它让**完全不用规划功能的人**也能记账——这是"能用"的底线；也是 §2 里那条「没有 trip 就全短路」的唯一豁免口。
- 白名单闸门必须反向钉住：`free` 桶与一切 expense 数据永不进分享载荷（§32 已有此纪律，§38 补一条针对 free 桶）。

## 4. 五个入口（按「用户此刻在哪」排，不按实现方便排）

### E1 · 行中：随手记 FAB 加一档「记开销」
旅行当天真正掏出来的动作只有两个——"记此刻"和"付钱"。
- FAB 弹层顶部做成**分段控件两档**：`记此刻 | 记开销`，默认仍停在「记此刻」，不改现有主流程与既有三屏状态机。
- 「记开销」屏的信息层级（328×723 主档）：
  1. 金额＝页面主角，超大字号 + 数字键盘直落（复用批次 23 的 textZoom 归一后的 1:1 口径）；
  2. 分类六枚 chip（沿用 `Expense.CATS`，默认选中「餐饮」，沿用 planner.js:1267 那条"高亮与提交读同一个值"的教训）；
  3. 顶部一行小字「记到：**<进行中的行程名>** ▾」，点开可换行程或选「未编排行程」；

## 5. 「计划 ≠ 实际」三条具体修法（对应 §2 的三个红灯）

1. **多走的天没有入口** → E2 的日列表按真实日期生成，`date` 有账就有一行，与 `days.length` 无关。不再需要"补空白日卡"。
2. **重切分静默搬钱** → 钱挂 `date` 后天然免疫；剩下唯一残留是「`date` 为空的旧账」。所以 `resplitTrip()` 在动刀前查一次：该趟存在 `date==''` 的条目 ⇒ 弹确认，列出「有 k 笔共 X 元没记日期，重排后它们会跟着新的第 n 天，确认？」两个选项：「保持原序号」/「跟着新排期」。默认停在"保持原序号"。
3. **CSV 与天气的日期错一天** → `buildCsv` 的 `dateOf` 改为**优先取条目自身 `date`**，只在为空时回落到 `dayDate(trip, day-1)`（planner.js:1351 那一行是唯一改动点）；天气位维持计划口径但标注（E5）。

**24-D 落地纪要（`trip.html` + planner 只加不减）**：

1. **`trip.html` 是 `logStart`/`realDays` 的第一个写入口**。24-A 落数据层时这两个字段只有读者（`expense.js:activeTripOf`／`expense.html`／`travel-notes.js`），也就是说「实际 M 天」这个读数当时是**孤儿**——界面上永远等于计划天数，因为没有任何一处能把它改成别的值。本页两个 `<input type="date">`／`<input type="number">` 各走 `patchTrip(fn)`：在 `tn_trips` 里按 id 找到那一条、只改那一个字段、整表回写。判据 T12 断言「写回的那条与种子逐键 diff = `["realDays"]`」——整表回写会拍平结构，这条 diff 就是它的守门人。清空日期是 `delete t.logStart`（回到计划口径），不是写 `''`。
2. **planner 侧一颗按钮都没删**。`planner.html` 只多一个 `<div id="tripHomeSlot">`，`renderResult()` 往里填一行 `<a class="btn ghost" href="trip.html?trip=…">`；`#actRow` 原有 12 颗原封不动，T35 用 12 项白名单**反查缺失**（读数 `[12, []]`＝数量对且一颗不缺，只数数量抓不到"删一颗加一颗"）。另在 `init()` 加 `?trip=<id>` 直达结果页：trip.html 顶栏那颗圆钮回规划页时要落回同一趟，否则用户从主页点进去看到的是空白规划态。本机没有这趟（换机／已删）只 toast 一句真话，不建桶。
3. **free 桶没有主页**：`?trip=free` 直接 `location.replace('expense.html?trip=free')`。给「未编排行程」造一个空壳 trip 对象等于在账本外多出一份行程数据，而它本来就没有排期可看。认不出的 id 走 `showUnknown()`，同样绝不建桶。
4. **票卡是异步的，守卫必须捕获当时的 id**：`TicketBox.list()` 走 IndexedDB，回来时用户可能已经换了另一趟。写成 `if (tripId !== (trip && trip.id)) return;` 是**恒等式**（守卫等于没有），正确写法是先 `var tid = tripId;` 再比 `tripId !== tid`。这类失效守卫在单机上永远看不出来。
5. **两条判据自身的坑**（不是产品缺陷，写进 `tools/smoke-trip.js` 头注释）：① `trip.html` 没有首启引导层，所以这一段**不需要** `tn_onboarded`（与 24-C 不同，别照抄）；② T26/T27 触发的 `.ui-nudge` 页内横幅活 10s 且固定在底部，正压着「记一笔」，T28 点击前必须先 `remove()`，否则报 `Node is either not clickable`——症状长得像弹层没打开。
6. **自查修掉的一处真缺陷**：零行程时 `#pickCard` 与 `#tEmpty` 同时 `display:block`，页面顶部露出一张空选择器卡（T07 抓到）。修法是 `list.length ? 'block' : 'none'`，并在空态补一条 free 桶指路「不排期，直接记一笔 →」——空态指路必须指着真能点到的地方（planner.html:147 那条老教训）。另把三处卡头小字链接改成 `.btn ghost wide`／`.t-acts` 里的按钮：文本链接在 328 主档下不足 44px，T31/T32 实测 `low:[]`。
7. **离线壳**：`node tools/gen-sw-shell.cjs` 后 `git diff sw.js` 恰 2 行（`trace-v78` → `trace-v79`、`+ './trip.html',`），SHELL 155 项（页面 19 / 核心 JS 28 / art 44）。顺带核出一条与本批无关的旧账：`CORE_JS` 名单里的 `tiles.js` 是**死名**（磁盘上没有，被 `.filter(existsSync)` 静默丢掉，所以名单 29 个名字打出来是 28 项），已写进 README，不在本批改。

## 9. 明确不做

| 不做 | 理由 |
| --- | --- |
| 行程费用估算（油费/过路费/多方式） | 用户已判「不做子，太复杂」（2026-10-05） |

## 10. 风险与对策

1. **迁移写盘把用户账本写坏** → 迁移只派生视图、不主动落盘；smoke 里加一条"迁移前后逐条金额求和相等"的硬断言（钱只认整数分，能精确比）。
2. **FAB 弹层加档踩坏随手记三屏状态机**（该面板曾出现皮肤层 `!important` 藏死保存键的前科）→ 分段控件只做显隐切换，不新增第三种屏态；改完必须复跑随手记既有 smoke。
3. **新页进 SHELL 后 gen-sw 顺带抹条目**（生成器抹过登记条目的前科）→ 跑完立刻 `git diff sw.js`，只允许版本号行 + 新页两行。
4. **一次动五个入口，回归面大** → 批次按 A/B/C/D/E 分开收口，每批独立全闸门复跑；旧入口一律保留。
5. **真机腿仍卡在解锁** → 24 批所有"手机上看着对不对"的结论都要等人工解锁补拍，不许用桌面截图代替（系统字体名在手机上全不命中的前科）。

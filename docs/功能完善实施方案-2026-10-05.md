## 0. 四条会改变方案形状的硬事实（先立，后面反复引用）

这四条是核查地基时撞出来的。它们不是"待办"，是**约束**——写方案时如果不把它们摆在最前面，第 1 项和第 4 项会照着不存在的机制设计。

### 0-1 · `tools/gen-tickets.js` 的写盘逻辑已经失效（第 1 项的真前置）

- 脚本 L46/L51 的替换目标字面量是 `var SEED = window.SITE_TICKETS_SEED || {};`；
- 而 `site-tickets.js:6` 现在写的是 `var SEED = window.SITE_TICKETS_SEED = {`。
- **后果链**：`next === file`（替换没命中）→ L56-57 自检把 `next` 装进沙箱，拿到的是**旧的 9 条**，而内存里合并后的 `seed` 是 9+新增 → `cnt !== Object.keys(seed).length` → **印「自检失败」exit 1，一个字都写不回**。
- 更阴的一种形态：**一个名字都没新增成功的那次跑（全部 FAIL/SKIP）会"绿灯"收工**——因为 `seed` 条数没变，自检通过，写回原文件。也就是说这个脚本现在的行为是「有成果必失败、无成果必成功」，恰好反了。
- 第二个独立缺陷：L49 `Object.assign({}, seed[k], { h: out[k].h })` **无条件覆盖 h**。高德那一页没返回营业时间时 `out[k].h === ''`（脚本自己会印 `EMPTY`），于是人工/历史种子行里的好 `h` 被空串抹掉。
- L46 那个 `var m = file.match(...)` 是死变量（正是漂移的化石：它匹配的就是旧字面量）。

**修法（三项一起，缺一仍会漂）**：
1. 替换目标改成正则、且**替换前断言恰好命中 1 次**：`/var SEED = window\.SITE_TICKETS_SEED = \{[\s\S]*?\n\};/`，命中数 !== 1 就 exit 1 并印原因；
2. 写回改成 `h` 空值不覆盖：`{ h: out[k].h || (seed[k] && seed[k].h) || '' }`，并把"这条这次是 EMPTY"记进末尾统计行；
3. **常驻闸门**（进 §27）：把"脚本里的目标字面量"与"`site-tickets.js` 里的实际声明行"做整串对账。这条是本次事故的根因治疗——字面量漂移在仓库里**从来没有闸门看过**，脚本坏了三天没人知道。

> 同一条教训适用于所有"脚本改数据文件"的工具：第 7 项要新建 `tools/gen-images.js`，**必须一出生就带这条对账闸门**。

### 0-2 · `usableInsets` 结构上算不出左右内缩（第 4 项的真前置）

批次 13 的可用视口模型（`topic-common.js:308 usableInsets`）只做纵向：
- `:311` 把 `ins.left / ins.right` 初始化成 0；
- `:326-327` 只做 `size.x - 40` 的横向夹取（防止标记贴边），**没有任何地方给 left/right 赋非零值**；
- `:319` 的成带判据 `if (r.height <= 0 || ix < el.width * 0.6) return;` 是"横向重叠够多才算一条带"，本质上是**上下缘**检测器。

所以「把侧栏名字塞进 `USABLE_BANDS:305` 就能复用整套内缩计算」这句上游判断**不成立**。双栏要先给模型加横向分支，而且加完之后有一处必须避开的雷（见第 4 项）。

### 0-3 · 产品没有任何通知 / 定时能力（决定第 3 项"提醒"长什么样）

- `MainActivity.java` 只有两条 JS 桥：`AndroidVoice` 与 `AndroidCard.updateCard`（`:414`）。**没有 `NotificationManager`，没有 `POST_NOTIFICATIONS` 权限申请。**
- `sw.js` 没有 `push` / `sync` / `showNotification` 任何一个事件监听。
- 现有的"到达提醒"（`wishlist.js:67-96`）是**一次性 `getCurrentPosition` + 页内横幅**，命中后 10s 自移除，没有开关键，调用点只有 `index.html:506` 和 `topic.html:198`。

**结论**：任何写"出发前推送提醒"的设计都是假的。第 3 项的提醒只有两条 honest 腿：①进产品时的页内横幅（复用既有那套）；②桌面小组件（`AndroidCard.updateCard` 那条腿已经在跑）。要真通知 = 改壳 + 重打包 + 权限弹窗，本方案**不做**，登记在第 9 节。

### 0-4 · `saveTextFile` 的 MIME 是硬编码的 `text/html`（决定第 2 项 ICS 怎么走）

- `MainActivity.java:381 saveTextFile(name, content)` → `:388` 处 MIME 写死 `"text/html"` → API≥29 走 MediaStore Downloads，回执 `window.__tnSaveDone(name|'err'|'need_perm')`（`:394/405/407`）。
- JS 侧落点：`planner.js:1489 saveTextFile`（GPX/CSV/ICS 都想过这道门）。
- **后果**：`.ics` 经原生桥落盘会被标成 HTML，Android 日历 / 系统"打开方式"选不到它，用户看到的是一个打不开的文件。GPX 现在其实就已经中招（只是没人拿手机直接开 GPX）。

**取舍（第 2 项按此实施，不另开讨论）**：导出主腿改 **Blob + `a[download]`**（浏览器/桌面腿一定对）；APK 腿在实机验证前不承诺——**降级方案是复制到剪贴板 + toast 说明**（剪贴板能力已有，`planner.js:1440 plannerCopyPlan` 就是它）。改壳侧 MIME 要重打包，与 #73 装机抽查撞车，排在第 9 节等点单。

### 3.4 UI 口径

- `topic-common.js:605` 的文案 `'核对'` 改成 **`更新于 ' + t.u`**。理由：`u` 是"这条什么时候被核验过"，"核对"读起来像动词、像提醒用户自己去核对；"更新于"才是它本来的语义，也是上游报告 §6 第 1 条点名的那行"高级感小字"。

### 4.2 ICS 实施（纯字符串，零依赖）
1. 新函数 `buildTripIcs(trip)`（放 `planner.js` 导出区，紧邻 `:1481`）。
2. **事件形状**（因为结构里没有时刻，诚实做全天事件，不要假装有时段）：
   - 一条总览全天事件：`startDate` 到 `startDate + days.length`，SUMMARY = trip.name，DESCRIPTION = 每日一行概要；
   - 每天一条全天事件：SUMMARY = `第N天 · <起城市>→<终城市>` 或 `第N天 · <城市>漫游`，DESCRIPTION = 逐个 stop 名 + 营业时间（走 `SiteTickets.get` 的**已有种子缓存**，没 Key 也不联网）+ 门票，LOCATION = 首个 stop 名，UID = `tripId-d<di>@lvyou-trace`。
   - `DTSTART;VALUE=DATE:20261005` 形式（全天事件用日期值，不带时区，**避开 VTIMEZONE 整块复杂度**，这是最省事且各家日历都认的做法）。
3. **四条必须做对的规范细节**（做错就是"导入失败"，用户只会说"打不开"）：
   - 输出**行结束符必须是 CRLF**；
   - TEXT 值里的 `\` `,` `;` 要反斜杠转义，换行转 `\n`；
   - 超过 75 **字节**的行要折行，续行以一个空格开头 ——**必须按 UTF-8 字节折，不能 `String.slice` 按码点折**（中文按字符切会把一个汉字切成两个非法字节序列，日历直接拒收）。实现走 `TextEncoder` 数字节；
   - 必需字段：`VCALENDAR` 的 `VERSION:2.0`/`PRODID`/`METHOD:PUBLISH`，每 `VEVENT` 的 `UID`/`DTSTAMP`/`SUMMARY`。
4. `startDate` 为空时的产品行为：菜单项**置灰 + 说明"要先在规划页选出发日期"**，点击给 toast；**绝不静默生成 1970 年事件**，也不擅自用 `createdAt` 顶替（那是"生成日期"不是"出发日期"）。
5. 导出通道（0-4）：主腿 Blob + `a[download]` 文件名 `行程名.ics`；`a.download` 在 `file://` WebView 里的行为**必须在实机验证后才允许写进 README**，未验证前 APK 腿走"复制到剪贴板 + toast"降级，并在收工账里明写"APK 腿未验"。
6. GPX 顺手同样改 Blob（同一个 MIME 硬编码病），但**不在本批动**，登记。

### 10.5 基线与风险
- 基线：**原则上不动**（只加属性不改视觉）。判据就是"基线一格没动"：改前只读跑 79 态要求逐条 0.00%，**如果动了说明顺手改了样式**（真回归）。唯一例外：`tabindex` 若带来 focus 环样式，则要么显式复用既有 focus 视觉（批次 12 已定"强聚焦"口径，`user-design-quality-bar`），要么本批不加 tabindex 只做 role/label —— **实施时先实测默认 focus 环在手机上是否可见**，再定这条。
- 风险：①`node-lod.js` 四处分层渲染 divIcon，漏一处就是"部分标记可访问、部分不可"，四处各钉一条锚；②读屏实机（TalkBack，一加 Ace 6T / ColorOS）**我们无法自动化**，只能承诺 DOM/快照层 + 登记"真机读屏未验"；③这一批在手机上"看不见"（用户只验 APK），但它是**已有功能的可达地基**，报告里要按第 3 类价值写，不要包装成体验升级。

**收工判据**：§36 绿 + smoke-aria ≥20/20 + 变异含"两层视野差"样本在案 + **基线只读 79/79 逐条 0.00%（证明没动样式）** + sw bump + `aria-live` 实测计数回写。

## 9. 明确不做（照抄上游 §4 的判断 + 本方案新增三条）

| 不做 | 理由 |
|---|---|
| 订票聚合 / 实时价格 / 酒店接口 | 需服务端与商业授权；商用评估已搁置 |
| 多人实时协同（S2-5）；真·AA 分账结算 | 需常驻服务；我们无账号无成员模型 |
| **系统通知 / 推送 / 定时唤醒**（本方案新增） | 0-3：桥里没有 `NotificationManager`，SW 没有 `push/sync`。要做得改壳 + 重打包 + 权限弹窗，收益排在 S1 全部之后 |
| **`saveTextFile` 的 MIME 通用化**（本方案新增） | 0-4：改壳要重打包，与 #73 撞车。第 2 项用 Blob 主腿 + 剪贴板降级绕开；GPX 同样中招但不动 |
| OSRM 步行/骑行公共实例（本方案新增） | 公开 OSRM 只提供 driving profile；承诺它必翻车（第 6 项已用本地档 + 高德 Key 腿替代） |
| **行程费用估算**（2026-10-05 追加讨论后用户判「不做，太复杂」） | 交通那一腿按出行方式**结构性分叉**：自驾要有油价 + 过路费、公共交通要有各段票价、骑行近乎零成本——**这三类数据源我们一个都没有**（实测：36 份 `*-data.js` 里 `price/ticket/fee/票价/费用` 全 **0** 命中；公交档在第 6 项已登记为不做）。门票那条腿只有 `site-tickets.js` 的 9 条种子，且 `p` 是**文案串**（"旺季 190 元 / 淡季 150 元"）能看不能加；要真算就得先拆 `pa/pi`，再长期人工维护一张价格表——收益/维护比不划算 |
| 但第 5 项**事后记账照做** | 记"实际花过的钱"不需要任何外部数据源，这正是它比"事前估算"便宜一个量级的根因：**估算的雷在数据，不在 UI**。所以第 5 项的预算入口仍是用户手填，别把它改造成"自动估算" |
| 矢量离线地图 / i18n / SSO / passkey / UGC / 插件与自建 MCP / Atlas 版图 / Immich·Strava 联动 | 上游 §4 全部照旧 |

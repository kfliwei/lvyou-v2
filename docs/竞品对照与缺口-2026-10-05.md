# 行迹TRACE × 外部旅行项目对照报告（2026-10-05）

> 问题：上网/GitHub 找旅行类 skill 与相似项目，对比我们还欠缺什么、需要完善什么。
> **本报告里所有内部数字都是我自己的 grep/解析实测**（子代理给的数我复核过，纠了三处，见 §7）；外部材料全部落到 `tools/out/ref-*-README.md`（调查临时件，未入库）。

评分维度取自 [tripprof 对 20 个行程 App 的横评](https://tripprof.com/en/blog/best-trip-planning-apps-2026/)：**行程构建 · 开销处理 · 目的地指南 · 打包清单 · 单据存储 · 团队协作 · 离线能力 · 地图集成**。该文结论里对我们最有用的一句：打包清单与单据存储**在多数规划器里是缺的**，而离线能力**几乎全在付费墙后面**。

另有一条行业事实值得记下：主流 skill 清单（[ComposioHQ/awesome-claude-skills](https://github.com/ComposioHQ/awesome-claude-skills) 7.6 万星、[VoltAgent/awesome-agent-skills](https://github.com/VoltAgent/awesome-agent-skills)）里**几乎没有任何旅行垂直 skill**——搜 travel/trip/itinerary/packing/flight 只命中 Stripe/Expo 之类的无关项。旅行 skill 目前只有「一次性生成攻略」这一种形态（见好、华行志），**没人做「本地数据 + 长期沉淀 + 离线」那一端**，那正是我们的位置。

## 1. 一句话定位

**八维里我们有 5 维能用、3 维为零（开销处理、打包清单、单据存储）；同时有一维是上面所有竞品都要付费或自建才有的：离线能力 + 数据自持。**

缺口不在"功能少得可怜"，而在**「行前」那一段整个不在产品里**：规划完 → 导出 → 换三个 App 去查预约、清单、票据、记账。用户的一趟旅行被产品切成两半。

## 2. S1 · 结构性缺口（补齐才算"能独立完成一次旅行"）

### S1-1 门票与营业时间：机制齐了，覆盖率只有 0.12%
- **实测**：`site-tickets.js` 种子 **9 条**（晋祠/平遥古城/云冈石窟/故宫/西湖/黄山/九寨沟…，`"u": "2026-10"`），而内置景点 **7515 条**（36 份 `*-data.js` 的 `"name":` 出现次数）、索引 **7794 条**（`tools/verify.js:71` 那颗常驻闸门自己打印的读数）。
- **机制其实已经很好**（`site-tickets.js:1-5, 100-127`）：三级 = 内置种子 → localStorage 30 天缓存（`tn_tk_` 前缀）→ 高德 v5 `business.opentime_week`；**同名异地保护**要求 POI 坐标落在景点 ±0.2° 内否则放弃（`:71-75`）；无 Key 直接 `cb(null)`；文件头写明「未收录就不显示价格行，绝不编造」。挂载点 `topic-common.js:596-597`。
- **使用后果**：排完 5 天行程，用户仍要逐个搜「要不要预约、几点开门、多少钱」——这正是"到门口进不去"那一类不可逆损失。故宫/九寨这种**必须提前预约**的，产品给不出提示。
- **修复方向**：`tools/gen-tickets.js` 已经能批量取高德营业时间（QPS 350ms、幂等可重跑、人工 `p/u` 原样保留）。把 7515 条 name 按城市分批喂进去即可；票价走人工/AI 辅助但**必须带 `u` 年月**。第一档目标建议 = 专题地图里 `flag` 标过的 1687 条（必去级），不要一上来追全库。

### S1-2 单据（机票/车票/酒店预订）：零承载
- **实测**：根目录全库无 `行程单|机票|车票|航班|高铁|boarding|flight|证件提醒` 的真实调用点；`site-tickets.js` 是**景点门票**不是票据。
- **对照**：TREK 有 **16 类预订**（状态、确认码、同行人、附件）、 flights/trains 支持多段 + 经停 + 每段时区，且能对 4,045 个内置机场解析当地时间；还能用 KItinerary 从 EML/PDF/PKPass/HTML 自动导入确认单；AirTrail 联动同步航班。AdventureLog 的行程里 flights/lodging/checklists 是一等公民。
- **使用后果**：行前最重要的一类「我手上有什么」不在产品里，于是规划成果必然出产品续命。
- **修复方向**：**不做订票**（无服务端、不做商业接口）。做「我的票」卡片：文本 + 附件走现成的 IndexedDB 媒体通道（相册已在这条腿上）+ 出发前提醒复用 `wishlist.js:67` 的到达提醒机制（3km 触发那套已经在跑）。

### S1-3 开销 / 记账 / 预算：零
- **实测**：全库 `预算` 命中全是工程口径（`planner.js:418` 是里程与时长切分、`visual-check.js` 是性能预算、`verify.js` 是挂点预算）；`icons.js:39` 有 wallet glyph 但**没有任何页面挂载**。
- **对照**：TREK 的 Costs 用**整数分**记账（避免浮点）、AA 或自定义份额、一笔多付款人、结算建议 + 结算日志、CSV 导出、每笔锁汇率（Frankfurter 免 Key）。这是旅行工具里复购最高的模块之一。
- **修复方向**：纯本地即可做——日卡级「今日花销」+ 行程汇总 + CSV 出。与现有 `TravelNotes.persist` diff 通道同构，不需要新存储层。工作量在这批里最大，适合单开一批。

### S1-4 行前清单（打包 / 待办 / 倒计时）：零
- **对照**：见好路书把「出发前倒计时（勾选式）+ 装备清单」列进**总览八件**；TREK 的 packing lists 有分类、管理员模板、负责人、三档可见性、「已打包 / 总数」行，行李称重是独立开关；还有 to-dos（负责人 + 到期 + 优先级 + 到期前提醒）。
- **我们的独特优势**：清单不必让用户白手起家——`*-data.js` 里 **7498 条都带 `elev`（海拔）与 `best`（最佳季节）**，可以直接按目的地的海拔档与季节预填「冲锋衣/氧气/防晒」这类条目。这是内置结构化数据才做得到的事。

### S1-5 导出：能给自己存档，不能进别人的日历
- **实测已有**：Markdown / 单篇 HTML（内嵌照片与原声）/ ZIP Vault（Obsidian 结构，`vault.js:3,9-11`）/ GPX 轨迹。
- **实测没有**：`BEGIN:VEVENT|text/calendar|jsPDF` 全库 **0 命中** → 无 ICS、无 PDF。
- **对照**：TREK 每行程与全行程各一条 **ICS feed**、GPX 导出，PDF 含封面/照片/日注/预订/开销且可逐日分页；见好的产物本身就是"打印三好看"的单文件 HTML。
- **修复方向**：ICS 是纯字符串拼接，**成本最低、感知最强**的一条（做完就能把行程推进系统日历）；PDF 不必引库，走「打印友好单文件 HTML + 系统打印」，与见好同一条路线，也避开给 APK 加依赖。

## 3. S2 · 可信度与体验缺口

### S2-1 事实没有「来源 + 核验日期」（最贴我们工程文化的一条）
- **实测**：`*-data.js` 字段普查为 name/desc/wiki/theme/region/lng/lat/label/elev/county/best/city/img/flag（`wiki` 有 7498 条，可当来源链接），但**没有任何"这条信息何时核验"字段**；只有 `site-tickets.js` 的 `u: 'YYYY-MM'` 有 freshness 概念。
- **对照**：华行志每条 attraction 都带 `sources` + `last_verified`，且**价格与预约规则刻意 nullable**——文件里原话「an unknown value is safer than a confident but outdated answer」，并提供 `freshness` / `integrity` 两个自检命令。见好则把它写成 skill 纪律：**价格纪律五条**（餐饮人均口径 / 路程时长写线路名 / 估算不豁免实查 / 价格多处同步 / 收录差集核查）与「图注落位对 ≠ 图内容对、数指标不算对比、价钱是挂牌价不是实付价」这些**真实翻车换来的规矩**。
- **为什么这条重要**：我们已经有 25 节常驻闸门保证"代码不许漂"，但没有一条保证"事实不许过期"。而旅行产品里过期事实比坏代码更伤信任。
- **修复方向**：所有事实型字段统一带 `u`（年月）；UI 上在门票/营业时间旁印「更新于 2026-10」；`verify.js` 加一节统计「超过 N 个月未核验」的枚数并设上限。**这行小字本身就是"高级感"**。

### S2-2 图片覆盖 75 / 7794
- **实测**：`site-images-local.js` 镜像 **75 张**（另有 1 个 `__missing` 键，共 76 个 `":`）；而 `*-data.js` 里带 `img` 外链的 **2120 条 = 28.2%**，那些是高德 `store.is.autonavi.com` 外链，**离线即断**。
- **使用后果**：绝大多数景点卡纯文字；专题地图离线时大面积无图（批次 4 的像素闸门因此专门拦 http，实景照片态本来零像素覆盖，已登记在 README 诚实欠账）。
- **修复方向**：以 `wiki` 字段为柄走 **Wikimedia Commons** 批量补图（免 Key、可商用；见好的默认图源也是它，且带"网络不可达自动降下一级图源"的三级链设计，值得照抄）。

### S2-3 「这一带还有什么」答不出
- **实测**：检索腿 = 内置全库 `search.html` + 高德 POI 手动查（`node-manager.html:203`、`planner.js:310`、`topic-common.js:545`）。没有"按当前视野拉 POI 分类"的能力。
- **对照**：TREK 有 POI explore（Overpass 按 viewport 分类拉 OSM）+ place enrichment（OSM/Wikipedia/Wikidata/Commons 补描述、事实、营业时间、照片候选）；导入支持 Google Maps/Naver 共享列表与 GPX/KML/KMZ。
- **修复方向**：explore-map 加「附近还有什么」，Overpass 免 Key；能与现有「必去/网红/海拔/主题」筛选同框，是我们内置数据用不到的补位。

### S2-4 不开车的人排线不合理
- **实测**：距离矩阵只有高德**驾车**（`planner.js:1221`，Key 读取 `:1244`）。
- **对照**：TREK 的路由是 OSRM 三模式（driving/walking/cycling）+ 自动排序用**最近邻再 2-opt**，且**锁定点与酒店锚点不参与重排**；公交门到门走 Transitous；trvl 那类做跨模式整程优化（换日价格、拆分航段、里程票甜点）。
- **修复方向**：①我们的 `mkLeg(matrix)`「一把尺子」口径已经就位，加 **OSRM 公共端点的步行/骑行档**（免 Key）就能覆盖"市内步行为主"的用户；②公交至少给"换乘方案 + 用时"占位而不是缺席。③顺带值得照抄的产品细节：**锁定的站不参与重排**（用户手动钉过顺序的，自动优化不许再动）。

### S2-5 协同只有只读，一起规划是空的
- **实测**：`share.html` 是只读渲染，且 `verify.js:1062` 明确禁止分享页对访客发任何第三方请求（隐私设计，不是缺陷）。没有回写通道。
- **对照**：TREK 有 WebSocket 实时协同、16 类动作 × 四档权限矩阵、可复用邀请链接（可选过期）、群聊/投票/共享笔记、以及"无账号 guest"。AdventureLog 支持邀请共同编辑。
- **判断**：真协同需要服务端，与"纯本地/自托管 WebDAV"的定位冲突。**下限方案**：把同一份行程 JSON 放上 WebDAV，进产品时按 `createdAt` 与逐日条目做冲突对比（已有 `backup.js` 的并集口径与 `sync-webdav.js` 通道，成本主要在冲突 UI）。

### S2-6 无障碍：薄且不均
- **实测**：根目录（排除 tools/）`aria-*` **93 处**、`role="` **25 处**，分布在 24 个文件里，其余页面为 0；无 `aria-live`，弹层/日卡/地图标记缺结构化 label。
- **对照**：TREK  Appearance 一档含 light/dark/跟随系统、7 套配色 + 自定义强调色、透明度、紧凑密度、reduce motion、**按层级调字号**；23 语言含阿拉伯语 RTL。
- **修复方向**：先补三类关键结构（日卡、地图标记、底部弹层）的 role/label + 状态变更 aria-live，再谈全站；我们已有 `prefers-reduced-motion` 全局覆盖与十档字号阶梯（批次 12 V3），这两条其实已领先。

### S2-7 平板/桌面只是"不变形"，不是"好用"
- **实测**：像素矩阵含 768×1024 与 1440×900，但都是移动单栏放大；批次 13 刚把「可用视口」模型建好（`usableInsets`/`contentBounds`/`fitUsable`）。
- **对照**：TREK 有独立 <768px shell（自己的 token、底导、safe-area，底导条目用户可配）。
- **修复方向**：768/1440 做「左列表 + 右地图」双栏。好消息是**新做的可用视口模型正好是双栏的前置**——侧栏宽度进 `BANDS` 名单就能复用整套内缩计算。

## 5. 我们独有、外部几乎没有的资产（补功能时别把它弄丢）

1. **离线优先 + 数据自持**：`sw.js` SHELL 147 项（含 16 个 html，实测 `sw.js:9-26`）+ 36 份数据 7515 条内置景点 + 75 张镜像实景 + 思源宋体子集两档进包；断网下 `share.html` 仍出 5 天 12 站（`smoke-share.js` 64 项实测）。外部同类里离线几乎都在付费墙后。
2. **零账号零云端**：Key 只在本机 localStorage（`travel-notes.js:6-28` 多站点注册表），备份三层排除密钥（`backup.js:60-63`）。
3. **WebDAV 自持同步 + 替换式恢复**：`sync-webdav.js`（push/pull/test/autosync/redact），`smoke-backup.js` 53 项真 round-trip 且验过「刷新后仍是 3 篇」（真进 IndexedDB）。
4. **随手记的录音→转写→三种风格 AI 润色**：`travel-notes.js:111,1190`。旅行 App 里少见。
5. **可复跑的观察纪律**：25 节常驻闸门 + 26 条变异自测 + 79 态像素基线逐条 0.00%。TREK 的 AI 使用声明里那句「"The AI wrote that" is not an answer any of us would accept」是同一取向，只是我们用闸门表达。
6. **Android 桌面小组件 + 长按快捷**：`TraceWidget.java:17`、`MainActivity.java:47,95,412,431,492`。这是"每天看见它"的入口，Web 产品没有。

## 6. 建议排序（对齐用户点单的「更有高级感 + 结合丰富功能」）

| 顺位 | 做什么 | 为什么排这个位置 | 量级 |
|---|---|---|---|
| 1 | 门票/营业时间批量覆盖（S1-1）+ 事实带 `u` 并显示「更新于」（S2-1） | 骨架与 `gen-tickets.js` 已在，是**最便宜的可见提升**，且直接服务"到门口进不去"；那行小字同时是信任面 | 0.5 人日（不含批量实查时间） |

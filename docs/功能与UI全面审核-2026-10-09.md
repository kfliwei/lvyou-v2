## 2. S1 — 会丢数据、会走到尽头、会读到假信息

### S1-1 「上传到云端」零确认 + 整包 PUT 覆盖，且自动上传会自己踩这颗雷
- **位置**：`settings.html:415-425`（`wdPushBtn.onclick` 里没有 `UI.confirm`）；`sync-webdav.js:152-176`（`push()` 直接 `PUT` 覆盖 `trace-full-backup.json`，无版本号/无条件 GET/无冲突检测）；`sync-webdav.js:235-256`（自动上传挂在 `TravelNotes._afterSave` 上，防抖 30s 后**自己调用同一个 push**，只在失败时 `UI.tileWarn`）；`sync-webdav.js:15` 注释把语义写死了：`push = 本机采集 → 整包 PUT 覆盖远端`。
- **使用后果**：换机、重装、或刚点过「清除全部数据」之后，只要误触一次「上传到云端」（或本地留了空库又恰好保存一次，自动上传就会自己发起），云端那份唯一的整包备份被本机空/旧数据**整包替换**。此时「从云端恢复」（`pull` 并集、本机优先）读到的也是被覆盖后的空包 → **恢复路径同时消失**。这是全站唯一不可逆的操作，却是唯一一个既没有确认框也没有远端版本保护的动作。
- **修复方向**：① push 前 `UI.confirm`，正文如实写出本机与云端各有多少条（`Backup.describe` 已有这个能力）；② 远端先 GET 一次，若远端 `createdAt`/记录数比本机新或多，就要求二次确认或改走「另存一份带时间戳的文件」；③ 自动上传这条腿要么只允许在**已完成一次手动首传**后开启，要么改成"覆盖前先落一份 `trace-full-backup.<ts>.json`"。

### S1-2 「清除全部数据」名不符实，且成功后谎报，还会触发 S1-1
- **位置**：`settings.html:581-586`（按钮/标题写「清除全部数据」，确认正文写「清除全部**游记**数据」，实际只调 `TravelNotes.clearNotes()`）；`travel-notes.js:2311`（`clearNotes` 完成后 `flash('已清除全部数据')`）。
- **使用后果**：三层不一致叠在一起。① 图册、账目、行程、心愿、AI/WebDAV 配置与口令、自建节点**一条都没删**，用户以为清干净了（把手机给别人、或退货前的场景是真事故）；② 那颗 toast 反过来把话坐实成"全清了"，没有任何一条提示告诉他还剩什么；③ 清完立刻走 `_afterSave` → 若自动上传开着，直接把 S1-1 的空包推上云端。
- **修复方向**：把这一颗改成「清除游记」，toast 同口径；需要真"全部数据"的出口应逐项列出清单（走 `backup.js` 的键白名单），并**先关掉 autosync 再清**。同类文案先例：`expense.html:326`「删了就找不回来」就是照实说，可作模板。

### S1-3 录完音点一下遮罩，内容就地作废；重新打开连草稿都不留
- **位置**：`travel-notes.js:643`（`mask.onclick = closePanel`，无条件关）；`travel-notes.js:1018-1027`（`closePanel` 只停录音、撤原生语音、复位 phase，不看有没有内容）；`travel-notes.js:981-1016`（尤其 `:998` 每次 `openPanel` 都重写 `#tnRaw` 的 innerHTML，新 textarea 是空的，且 `:1003` 把保存钮重新置灰）。
- **使用后果**：这是产品最核心的动作（站在景点前对着手机说一段话）。说一半手滑碰到边缘 → 面板收起、录音被 `rec.stop()`；再点进来时，转写文本、已拍的附着照片槽、标题、标签全部是初始状态，**没有任何一处提示"上一条没保存"**。用户会以为 App 吞了他的记录（这条与历史上「随手记面板润色结果不可见」是同一类信任损伤）。
- **修复方向**：`closePanel` 前加一条内容判定（`state.raw` 或 textarea 非空或已有照片）→ 走 `UI.confirm`；或在 `state` 里留 `draft` 快照，`openPanel` 时若有同点草稿就恢复并说明"接上次的草稿"。遮罩点击改成只在 idle 态直接关，编辑/已录态一律走确认。

## 3. S2 — 主干流程有断点 / 看得见点不着 / 自家标准没铺开

1. **「记录」FAB 是一次整页跳转，不是打开面板。** `nav.js:14` 把中间那颗做成 `href:'index.html?shortcut=anywhere'`，`nav.js:35` 渲染成 `<a>`；`index.html:387-392` 在页面加载后 `setTimeout(...,600)` 才发起。后果：在首页按=重载一次首页（丢当前滚动位置与在途状态），在别的 Tab 按=跨文档跳转 + 600ms 白等一下才开始定位；跨文档转场动画也会与这次重载打架（批次 25-C 已记录过 `trip.html` 转场中断的假红）。方向：`nav.js` 里这颗改成拦截 `click` + `preventDefault()`，同源页面直接调 `window.__tnAnywhere()`，只有跨页才走导航。

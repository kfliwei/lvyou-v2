## 2. S1 — 会丢数据、会走到尽头、会读到假信息

### S1-1 「上传到云端」零确认 + 整包 PUT 覆盖，且自动上传会自己踩这颗雷
- **位置**：`settings.html:415-425`（`wdPushBtn.onclick` 里没有 `UI.confirm`）；`sync-webdav.js:152-176`（`push()` 直接 `PUT` 覆盖 `trace-full-backup.json`，无版本号/无条件 GET/无冲突检测）；`sync-webdav.js:235-256`（自动上传挂在 `TravelNotes._afterSave` 上，防抖 30s 后**自己调用同一个 push**，只在失败时 `UI.tileWarn`）；`sync-webdav.js:15` 注释把语义写死了：`push = 本机采集 → 整包 PUT 覆盖远端`。
- **使用后果**：换机、重装、或刚点过「清除全部数据」之后，只要误触一次「上传到云端」（或本地留了空库又恰好保存一次，自动上传就会自己发起），云端那份唯一的整包备份被本机空/旧数据**整包替换**。此时「从云端恢复」（`pull` 并集、本机优先）读到的也是被覆盖后的空包 → **恢复路径同时消失**。这是全站唯一不可逆的操作，却是唯一一个既没有确认框也没有远端版本保护的动作。
- **修复方向**：① push 前 `UI.confirm`，正文如实写出本机与云端各有多少条（`Backup.describe` 已有这个能力）；② 远端先 GET 一次，若远端 `createdAt`/记录数比本机新或多，就要求二次确认或改走「另存一份带时间戳的文件」；③ 自动上传这条腿要么只允许在**已完成一次手动首传**后开启，要么改成"覆盖前先落一份 `trace-full-backup.<ts>.json`"。
- **当前进度（2026-10-09 批次 32-B 收口，实测数字）**：
  - **判定只有一个出口**：`coverPlan(env, remote)`（`sync-webdav.js:199`）＋`lostIds`（`:192`）按 **id 逐条比**，不按条数差猜；写远端只有一个 `putEnv`（`:160`）。出口只有两支：`confirmPush`（手动，`:250`）与 `pushAuto`（自动，`:272`）；**裸 `push` 在产品代码里 0 个调用者**（全量扫描读数：产品侧 0／`tools/` 8），它只给验证脚本走传输链路。
  - **确认层分四档说话**（`pushWords`，`:228`）：云端读不到 / 云端那个文件不是行迹备份 / **云端有本机没有的记录**（逐类报「N 篇游记、N 本图册、N 项数据在这台设备上找不到」）三档都是 `danger:true` + okText「仍然覆盖」；只有「云端已有的记录这台设备全都有」那一档才不危险。**没有确认框可用时直接报错，不静默覆盖**（`:262`）。
  - **自动上传那条腿改成「会丢就一次都不写」**：`!p.risky` 才 `putEnv`；risky 时只 `record(false, '自动上传已跳过：…')` + 一条 `UI.toast`，且**绝不弹确认层**（没有任何一次点击，弹给谁看都是卡死）。浏览器腿 I19 实测到点自跑 PUT 自增 **0**、云端仍是 3 篇；I20/I21 分别钉「跳过原因写进 `tn_webdav_last` 且 `ok:false`」与「屏上真飘出那句 toast」；I22 断言全程无确认层、I23 断言拒绝这一覆盖不等于替用户关功能；I24 反向对照「不 risky 时照旧 PUT 一次」——这一节不是把自动上传整个关掉。
  - **顺带查出两处「设计内静默」**：① `remoteInfo` 的 404 分支原本 `cb()` 后不截断 Promise 链 → 同一调用者收两次回调，「远端没有文件」被二次报成「备份内容不是对象」（实测炸在 I14：先直传成功又弹一层危险确认），已补 `once()` + `settled` 守卫；② `UI.tileWarn` 的签名是 `(layer, name)`，第一行 `!layer.on` 就 `return`——把告警文案当第一个实参传进去，「自动上传已跳过」「云同步失败」两句**从来没上过屏**，两支都改回 `UI.toast`。

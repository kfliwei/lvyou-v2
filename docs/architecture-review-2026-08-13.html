05 本轮新发现（按优先级）

P1 · 离线瓦片被清空

sw.js activate 误删 trace-tiles

activate 中 ks.filter(k => k !== CACHE) 删除所有非当前版本缓存，离线瓦片包（trace-tiles）也被一并删除。每次 SW 升级，用户下载的离线瓦片全部丢失，需重新下载。

P1 · 新引擎三处脱节

node-lod.js 未入离线清单

6 处页面已引用 node-lod.js?v=14 并调用 NodeLOD.init，但 sw.js SHELL、gen-sw-shell.cjs 的 CORE_JS 列表均无它，且文件未 git add。离线访问专题页 → NodeLOD 未定义 → 地图渲染崩溃（8/12 geo.js 事故同款模式）。

P1 · 版本号机制脱节

手写 ?v=N 与 SHELL 不同步

node-lod.js 已 v14、其余文件 v=1/2，各计各的；SHELL 里全是无版本裸路径，URL 精确匹配下预缓存命中不了带 query 的请求。每次改动需人肉同步 3 处，必有遗漏。

P2 · 进行中工作未提交

9 文件 + node-lod.js 游离在 git 外

8/12 12:09 之后的改动（4 老专题接入 LOD 等）未提交；CRLF/LF 行尾混乱使 git diff 伪爆 3948 行（真实仅 212+/137-），审查噪音巨大。

P2 · 兜底数字已过期

首页计数 fallback 硬编码

cntOf('cz','凡一百六十一处') 等 8 处 fallback 与真实数据不符（cz 161→179、sc 412→391、gs 303→305、xj 287→298、gz 321→323）。TC 优先逻辑正确，但兜底反而兜出错误数字。

P2 · 敏感值掩码残留

KEY='***' / AMAP_KEY='9e530e…4149'

wishlist.js 的 localStorage key 被掩码成 '***'（注释却写 tn_wishlist）；4 个专题页的 AMAP_KEY 是含省略号的假值（死代码，瓦片/导航均不用 key，无功能影响）。疑似生成工具自动打码痕迹，应清理或补真实值。

P2 · 数据双份 + 命名误导

qz-data.js 实为青藏数据

文件名叫 qz（泉州缩写），实际存青藏 189 节点（青海10+西藏164+新疆15）；与全国地图的 qh-data.js / xz-data.js 双份维护，扩数据时易不同步。

P2 · 收敛不彻底

geo.js 收敛残留

topic-common.js 仍残留 _A/_EE 常量死代码；esc()/flash() 等工具函数仍每文件一份；sw.js RUNTIME 正则与通用 SWR 分支逻辑重复（冗余分支）。

P3 · 观察项

LOD 全量重建 / 未转义

moveend 全量 clear+重建 marker（220ms 防抖缓解）；clusterIcon 的 label 直接拼 HTML（本地静态数据，风险低）；levelCache 需外部调 refresh() 清缓存，筛选联动易漏。
